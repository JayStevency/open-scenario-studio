# 시나리오 스튜디오 요구사항 명세서

버전 v0.1 · 초안

SC · BR · CAP · DEV 프레임워크를 도구로 옮긴 웹 애플리케이션. 시나리오와 동작 규칙을 앱 안에서 직접 작성·수정·삭제하고, 규칙 사이의 관계를 명시하고, 정합성 문제를 자동으로 찾아내는 것을 목적으로 한다.

## 1. 배경과 목적

현재는 엑셀 시트와 별도 다이어그램 문서로 시나리오를 관리한다. 두 가지가 반복해서 문제가 된다.

첫째, 원본 데이터의 추가·수정·삭제가 관리되지 않는다. 시트를 고치면 다이어그램과 개수가 어긋나고, 누가 왜 고쳤는지 남지 않는다.

둘째, 규칙(BR) 사이의 관계를 표현할 자리가 없다. 시나리오 사이의 전이는 그릴 수 있지만 규칙 하나가 다른 규칙의 선행 조건이거나 예외 처리라는 사실은 문장 속에만 있다.

이 도구는 앱을 원본으로 삼고 엑셀을 내보내기 산출물로 내린다. 데이터를 한 곳에서 고치면 관계도, 편성 보드, 검사 결과가 함께 갱신된다.

## 2. 범위

**포함**

시나리오·규칙·관계·기능 그룹·개발 시나리오의 작성과 관리, BR 간 관계, 정합성 검사, 변경 이력, 엑셀 내보내기, 데스크톱 웹.

**제외**

요구사항 추적 매트릭스, 테스트 케이스 관리, 일정·공수 산정, 이슈 트래커 연동, 모바일 화면, 엑셀 가져오기(1차 범위 제외).

적용 대상은 로보택시 프로젝트에 한정하지 않는다. 시나리오 유형, 담당 주체 값, 라이프사이클 단계는 프로젝트별로 설정 가능한 목록으로 다룬다.

## 3. 사용자와 권한

| 역할 | 하는 일 | 권한 |
|---|---|---|
| 기획자 | 시나리오와 규칙 작성, 태깅, 관계 정의 | SC · BR · REL · LINK 전체 편집 |
| 개발 리드 | 기능 그룹 묶기, 개발 시나리오 편성 | CAP · DEV 편집, BR 읽기 · 담당 주체 편집 |
| 검토자 | 확인과 의견 남기기 | 읽기 + 메모 작성, 상태를 검토 필요로 변경 |
| 관리자 | 프로젝트 생성, 목록값 설정, 사용자 관리 | 전체 |

여러 팀·사업부가 사용하므로 프로젝트 단위로 데이터를 분리하고, 사용자는 프로젝트별로 역할을 부여받는다.

## 4. 데이터 모델

여섯 개 엔티티. ID는 사람이 읽고 부를 수 있게 부여하며, 삭제한 ID는 재사용하지 않는다.

| 엔티티 | 필드 |
|---|---|
| `SC` 시나리오 | id · 명칭 · 표시명 · 영역 · 트리거 · 종료 조건 · 라이프사이클 단계 · 좌표(x, y) |
| `BR` 동작 규칙 | id · sc_id · 규칙 문장 · 유형 · 담당 주체 · 적용 조건 · 상태 · 미결 사항 |
| `REL` 시나리오 관계 | id · from_sc · to_sc · 종류(전환·분기·재실행·준용) · 발생 조건 · 근거 br_id |
| `LINK` BR 간 관계 | id · from_br · to_br · 종류(선행·예외·대체·데이터 의존) · 비고 |
| `CAP` 기능 그룹 | id · dev_id · 명칭 · 설명 · 포함 br_id 목록 |
| `DEV` 개발 시나리오 | id · 명칭 · 설명 · 담당 · 선행 dev_id · 검증 기준 |

**관계 규칙**

- BR은 정확히 하나의 SC에 속한다.
- BR은 최대 하나의 CAP에 속한다(미배정 허용, 검사 대상).
- CAP은 정확히 하나의 DEV에 속한다.
- LINK는 SC 경계를 넘어 연결할 수 있고 방향이 있다.
- SC를 삭제하면 소속 BR과 연결된 REL을 함께 삭제할지 묻는다.
- BR을 삭제하면 해당 BR을 참조하는 LINK와 CAP 배정을 자동 해제한다.

## 5. 기능 요구사항

### FR-000 공통 셸

| 번호 | 요구사항 |
|---|---|
| FR-001 | 헤더에 프로젝트명과 시나리오·규칙·관계·기능 그룹 건수를 표시한다. |
| FR-002 | 다섯 화면(BR 시트 · 관계도 편집 · CAP·DEV 편성 · 시나리오 상세 · 검사)을 탭으로 전환하며, 각 화면의 필터·선택 상태를 세션 동안 유지한다. |
| FR-003 | 검사 탭에 미해결 지적 건수를 뱃지로 표시한다. |
| FR-004 | 모든 편집은 즉시 저장하고 저장 상태와 마지막 변경 내용을 헤더에 표시한다. 별도 저장 버튼을 두지 않는다. |
| FR-005 | 전체 데이터를 엑셀에서 열리는 표 파일로 내보낸다. 규칙, 시나리오 관계, BR 간 관계, 기능 그룹, 개발 시나리오를 각각 시트로 구분한다. |

### FR-100 BR 시트

원본 데이터 관리 — 우선순위 최상

| 번호 | 요구사항 |
|---|---|
| FR-101 | 규칙을 표 형태로 나열한다. 열은 BR ID · 시나리오 · 유형 · 규칙 문장 · 담당 주체 · 기능 그룹 · 상태. |
| FR-102 | 각 셀을 표 안에서 바로 편집한다. 별도 상세 화면으로 이동하지 않는다. |
| FR-103 | 규칙을 추가·복제·삭제한다. 추가 시 현재 필터의 시나리오를 기본값으로 넣는다. 복제는 원본 바로 아래에 상태 초안으로 만든다. |
| FR-104 | 시나리오 열을 바꾸면 규칙이 다른 시나리오로 이동한다. |
| FR-105 | 규칙 문장 검색과 시나리오·유형 필터를 조합해 걸러 본다. 표시 건수를 보여준다. |
| FR-106 | 담당 주체나 기능 그룹이 비어 있는 셀은 경고색으로 표시한다. |
| FR-107 | 유형·담당 주체·상태의 선택 목록은 관리자가 프로젝트별로 설정한다. |
| FR-108 | 삭제 시 해당 규칙을 참조하는 BR 간 관계와 시나리오 관계의 근거 규칙 지정을 함께 정리하고, 무엇이 함께 지워지는지 알린다. |

| FR-204 | 화살표나 조건 문구를 선택해 관계 종류·발생 조건·근거 규칙을 수정하거나 관계를 삭제한다. 근거 규칙 선택 목록은 출발 시나리오의 규칙으로 한정한다. |

| FR-207 | 관계 목록을 목록 형태로도 제공하고, 항목 선택 시 다이어그램에서 강조한다. |

### FR-400 시나리오 상세 · BR 간 관계

신규 기능 — 우선순위 최상

| 번호 | 요구사항 |
|---|---|
| FR-401 | 시나리오를 선택해 명칭, 규칙 목록, 관계 요약(들어오는 · 나가는 · BR 간)을 본다. |
| FR-402 | 규칙 사이의 관계를 만든다. 기준 규칙은 현재 시나리오의 규칙에서, 연결 대상은 전체 규칙에서 고른다. |
| FR-403 | BR 간 관계 종류는 선행 · 예외 · 대체 · 데이터 의존으로 하고, 프로젝트별로 목록을 조정한다. |
| FR-404 | 기준 규칙과 연결 규칙 중 하나라도 현재 시나리오에 속하면 관계를 목록에 보여준다. 관계는 개별 해제한다. |
| FR-405 | 같은 두 규칙 사이에 같은 종류의 관계를 중복 생성하지 않는다. 자기 자신과는 연결하지 않는다. |
| FR-406 | 데이터 변경을 자동으로 이력에 기록한다. 기록에는 시각, 대상 ID, 변경 내용, 작성자를 남긴다. |
| FR-407 | 사용자가 결정 사항이나 질문을 메모로 남기고, 자동 기록과 함께 시간순으로 본다. 시나리오별로 걸러 본다. |

### FR-500 정합성 검사

데이터가 바뀌면 즉시 다시 계산한다. 각 항목은 지적 건수와 해당 ID 목록을 보여주고, 목록이 길면 앞 6건만 적고 나머지는 건수로 접는다.

| 번호 | 검사 | 판정 |
|---|---|---|
| FR-501 | 담당 주체 미지정 | 경고 — 담당 주체가 빈 규칙 |
| FR-502 | 기능 그룹 미배정 규칙 | 경고 — 어떤 CAP에도 속하지 않는 규칙 |
| FR-503 | 조건 없는 관계 | 경고 — 발생 조건이 빈 REL |
| FR-504 | 근거 규칙 없는 관계 | 경고 — 근거 br_id가 빈 REL |
| FR-505 | 예외 규칙이 없는 시나리오 | 경고 — 규칙 4건 이상인데 예외 유형이 0건 |
| FR-506 | 한쪽 흐름만 있는 시나리오 | 정보 — 들어오는 또는 나가는 관계가 없음 |
| FR-507 | 공통 모듈 후보 | 정보 — 3개 이상 시나리오에 걸친 CAP |
| FR-508 | 검토 필요 상태 | 경고 — 상태가 검토 필요인 규칙 |

## 7. 현재 프로토타입과의 차이

동작하는 프로토타입은 다섯 화면과 검사 8종을 모두 구현했다. 아래 항목은 명세에는 있지만 프로토타입에 없다.

- 저장 위치가 브라우저다. 서버 저장, 다중 사용자, 권한, 충돌 처리는 개발 대상이다.
- 사용자 계정이 없어 이력에 작성자가 남지 않는다.
- 유형·담당 주체·상태 목록이 코드에 고정되어 있다. 관리자 설정 화면이 없다.
- 엑셀 가져오기가 없다. 내보내기만 있다.
- BR 간 관계의 중복·자기참조 방지(FR-405)와 되돌리기(NFR-04)가 없다.
- 시나리오의 트리거·종료 조건·라이프사이클 단계 필드가 화면에 없다.

## 8. 미결 사항

| 항목 | 필요한 결정 |
|---|---|
| 담당 주체 96건 전 건 미지정 | 원본 엑셀에서 값을 받거나, 기획자가 앱에서 채운다 |
| 엑셀 가져오기 필요 여부 | 기존 시트를 한 번만 옮기면 되는지, 계속 왕복하는지 |
| BR 간 관계를 다이어그램으로 볼 필요 | 목록만으로 충분한지, 규칙 단위 그래프 화면이 필요한지 |
| 개발 시나리오의 선행 관계·검증 기준 | 데이터 모델에는 있으나 화면에 없다. 편성 보드에 넣을지 |
| 승인 흐름 | 상태를 확정으로 바꿀 권한을 누가 갖는지 |
